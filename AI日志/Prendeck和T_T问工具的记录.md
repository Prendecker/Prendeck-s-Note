## 1. api_dump Program.cs -- How It Works

**File:** `F:\XJXJXJXJXJXJXJXJ\st\steamapps\common\tModLoader\ModSources\PrendeckOddments\Tools\api_dump\Program.cs`

**Purpose:** A standalone C# top-level-program that uses `System.Reflection.MetadataLoadContext` to read tModLoader.dll *without actually loading it into the runtime*. This avoids needing FNA, XNA, or any game runtime dependencies. It dumps every public type's full API signature (including **return types**, which the official tModLoader.xml XML docs mostly lack) into a single JSON file.

**Command-line interface:**

```
api_dump <tModLoader目录> <输出JSON路径> [命名空间前缀,逗号分隔]
```

**Key steps in the program:**

1. **Assembly resolution** -- Collects DLLs from three locations (the .NET runtime dir, the tModLoader root, and the `Libraries/` subdirectory recursively), deduplicates by filename, and feeds them into a `MetadataLoadContext` + `PathAssemblyResolver`.
2. **Type pretty-printing** -- A `Pretty(Type)` function converts CLR full names (`System.Int32`) into C# keywords (`int`), handles generics, arrays, and by-ref types. A `Simplify()` helper strips namespaces for readability.
3. **Type iteration** -- Calls `asm.GetTypes()`, filtering to public types only. Skips compiler-generated types (names containing `<` or starting with `__`). Optionally filters by namespace prefix. Classifies each type as `class`, `struct`, `enum`, or `interface`.
4. **Member extraction** -- For each type, iterates over:
  - **Methods** (`BindingFlags.Public | Instance | Static | DeclaredOnly`): captures name, return type, `static`/`overridable`/`abstract`/`obsolete` flags, and parameter details (type, name, optional, default value, out).
  - **Properties**: captures name, type, whether get/set are public, and static flag.
  - **Fields**: captures name, type, static, readonly, const.
5. **XML doc key generation** -- Produces keys in the same format tModLoader.xml uses (`T:`, `M:`, `P:`, `F:` prefixes) so downstream tools can join signatures with XML documentation text.
6. **Output** -- Serializes the entire structure to a single JSON file with `WriteIndented = false` (minified). The output includes `source` (dll path), `generatedFrom` (version), `namespaces` (sorted deduplicated list), and `types` (the full dump). It intentionally does **not** include a timestamp to keep output deterministic.

**Dependency:** Only `System.Reflection.MetadataLoadContext` version 8.0.0 (defined in the .csproj). Targets `net8.0`.

"我想实现XXX效果"
    ↓
用 api_lookup.py 搜相关关键词
    ↓
找到可能的 API → 看签名和返回值
    ↓
用 -u 看 ExampleMod 里别人怎么用的

    ↓

所以教学顺序应该调整一下：

3. **教你从 ExampleMod 代码里"抄作业"**（找到用法 → 理解 → 改成自己的）

## 🤖 tModLoader导师

说实话，skill 文件夹**不需要塞太多东西**。

Cherry Studio 的 skill 机制本质是：触发时把 SKILL.md 的内容加载到上下文里。它不像 npm 包那样有"附带资源"的概念——塞了别的文件也不会自动加载。

**如果想放参考资源**，更好的地方是：


| 放哪里          | 放什么           | 为什么              |
| ------------ | ------------- | ---------------- |
| `Tools/`     | 代码模板、CSS 动画片段 | 跟开发工具放一起，随时能用    |
| `便携式教学越用越全/` | HTML 模板文件     | 教学文档直接从模板改       |
| `AI日志/`      | 代码速查卡         | 按需查，不占 skill 上下文 |


**唯一值得考虑加进 skill 目录的**：一个 HTML 模板文件。比如你以后做教学文档时，每次都要重新写暗色主题、泰拉配色、Prism.js 引入……有个模板直接复制改就行。

但这个模板放 `Tools/` 更合适，因为它是"开发辅助工具"而不是"skill 的一部分"。

所以结论：**skill 目录保持现在这样就好**，一个 SKILL.md 足够了。想加模板的话放 Tools 里~
